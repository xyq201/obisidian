# 每日化妆品知识系统学习 → 海报风 Word/HTML 总结 → 同步 GitHub（灵感库版）
# 模型由调度后端指定；本提示自包含环境修复，使独立会话也能上传
# 定位：本任务是【第一级·灵感库】产出。长文入 灵感库/，由用户阅读后让我"加工"才进 Topics（知识库）。

0. 环境准备（关键：自动化在独立会话运行，需自恢复 GitHub 连接）：
   - 凭证：独立会话依赖 `~/.github_pat` 与 sync-obsidian-kb.sh 的 ensure_gh 自动登录（已配置，无需在脚本内写明文令牌）。如环境缺失，自行 `export GITHUB_PAT=<你的令牌>` 兜底。
   - 若 /workspace/obisidian 不存在，先 clone：
     git clone https://github.com/xyq201/obisidian.git /workspace/obisidian
   - cd /workspace/obisidian
   - 拉取最新并用仓库内 sync-obsidian-kb.sh 自带的 hosts 自愈 + gh 自动登录：
     bash ./sync-obsidian-kb.sh pull
     （脚本会自动把 github.com 解析切换到出网代理放行的真实 IP，并在 gh 未登录时用 $GITHUB_PAT 自动登录；若仍失败，按脚本报错停止，不要伪造内容。）

1. 选题——每天换一个不同的主题：
   - 扫描 灵感库/ 已有文件名，提取已覆盖主题。
   - 从「主题轮换清单」按顺序选「最近 15 天内未覆盖」的下一个；全覆盖则从头循环。保证今天与昨天不同。
   - 轮换清单：
     1) 神经美容与皮肤-脑轴
     2) 医美术后屏障修护与泛红管理
     3) PLLA 聚左旋乳酸与胶原再生
     4) 皮肤屏障结构、神经酰胺与砖墙模型
     5) 透皮递送与促渗技术
     6) 光老化机制与光防护
     7) 黑色素生成与分区美白/色斑
     8) 痤疮的免疫-代谢轴与屏障修护
     9) 抗氧化网络、自由基与抗糖化
     10) 炎症与敏感肌（神经源性炎症/TRPV1）
     11) 洗护与头皮微生态
     12) 唇部护理与唇纹机制
     13) 彩妆肤感、持妆与粉体技术
     14) 化妆品功效评价与人体试验设计
     15) 原料创新趋势（肽/发酵/植物外泌体/重组胶原）
   - 优先覆盖用户聚焦方向（神经美容/医美术后/PLLA），再按清单轮换。

2. 多源系统学习（多轮检索，模拟约 1 小时；每类信源 2–3 次检索/抓取）：
   - 国内外前沿研究：WebSearch「<主题> mechanism review 2025 2026 / PubMed / clinical study / MDPI / ScienceDirect」，优先综述与临床；WebFetch 抓 1–2 篇核心原文提取机制与数据，记录真实 URL。
   - 公众号/行业权威资讯：WebSearch「<主题> 化妆品 趋势 2026 / 成分 前沿」，参考 研发权威资料清单.md 第四部分（青眼、美妆头条、聚美丽、中国香妆、妆研24小时等）观点与数据，记录真实 URL。
   - 经典书籍依据：引用董银卯《化妆品配方设计6步》、刘玮《皮肤科学与化妆品功效评价》、《Cosmeceuticals》、《Handbook of Cosmetic Science and Technology》作理论锚点（标注书名，无需联网）。
   严禁编造文献；每条结论尽量标来源。

3. （可选）配图：若当前 agent 可用 ImageGen 工具，生成 2 张主题科普配图（封面主图 + 机理示意图），保存为 PNG 到 灵感库/ 目录并记下路径；若不可用则跳过，生成器会用 CSS 信息图示兜底，不阻塞流程。

4. 写结构化内容 JSON：灵感库/YYYY-MM-DD-<slug>-content.json，严格按 make_learning_docx.py 的 JSON schema（title/subtitle/meta/sections[{type:callout|h|p|bullets|table}]/footer/references，可选 images:[{role,path,caption}]）。要求：
   - 双视角：callout（「一句话结论（双视角）」「产品经理视角」）与分段，服务工程师（机制→原料→添加量→配伍/pH/稳定→功效评价/法规）与产品经理（市场数据、消费者语言、宣称边界）。
   - 工程师视角必须给「靶点→原料→建议添加量→配伍/pH/稳定要点」表格（≥4 行）。
   - 语言：行内术语（TRPV1/ECS/HPA/TEWL）+ 消费者大白话。
   - 中文字数 ≥ 1000；结构：机理/前沿证据/工程师配方落地/产品经理市场沟通/合规红线/行动清单。
   - 排版美观：用 callout 承载重点、bullets 列要点、table 放配方，避免大段纯文字（用户反馈原文太密集太干）。
   - references（必填）：每项 {title, url}，只列真实抓取/检索到的出处，URL 真实可访问，禁止编造；书籍无可靠链接可留空 url。
   - images（可选）：若有配图，列 [{role:'cover'|'diagram', path:'灵感库/xxx.png', caption:'...'}]。

5. 生成海报风文档：
   - 若 python3.11 -c "import docx" 失败，先 sudo pip3 install python-docx
   - python3.11 make_learning_docx.py "灵感库/YYYY-MM-DD-<slug>-content.json" "灵感库/YYYY-MM-DD-<主题>.docx"
   - python3.11 make_learning_html.py "灵感库/YYYY-MM-DD-<slug>-content.json" "灵感库/YYYY-MM-DD-<主题>.html"
   （生成器已升级为海报风：封面色块、分区配色、留白宽松、重点高亮、嵌入 references 超链接；若有 images 则嵌入配图。）

6. 提交推送：bash ./sync-obsidian-kb.sh sync "kb: 每日系统学习(灵感库) YYYY-MM-DD <主题> (海报风 Word/HTML)"

7. 汇报：今日主题（与昨日是否不同）、信源覆盖（类/数/链接数）、docx 与 html 路径及中文字数、是否推送成功、是否含配图；并提示"已入灵感库，请阅读后让我加工成知识块"。某类信源不可达则说明缺失，不编造。

说明：只做知识学习与文档产出+同步，不改其他 vault 结构；gh/网络不可用立即报告停止。
