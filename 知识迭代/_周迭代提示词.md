# 知识库周期迭代 · 定时任务权威提示词（任务 #迭代任务 使用）

> 本文件是周期迭代任务的「权威提示词」，由 `scheduler-api.sh create` / `update` 注入。固化在仓库内防止沙箱重置丢失；不写任何明文令牌，凭证依赖 `~/.github_pat` + 脚本自动登录。
> 配套说明见同目录 `_迭代协议.md`；游标 `_迭代状态.md`；连接网络 MOC `连接网络.md`。

---

执行每周「知识库周期迭代」任务：把本周增量**连成网 + 迭代出新观点**，让知识库从收藏夹变成会复利的网络（姜胡说：素材相互链接 / 成长飞轮 / 经验复利）。

## 0. 环境与凭证（关键：避免孤立沙箱会话失败，切勿写死旧 IP）
- 进入仓库：`/workspace/obisidian` 不存在则 `git clone https://github.com/xyq201/obisidian.git /workspace/obisidian` 并 `cd /workspace/obisidian`。
- 运行 `bash ./sync-obsidian-kb.sh status`：脚本自动完成 hosts 动态自愈（探测出网代理放行的 GitHub 前端 IP）+ gh 自动登录（读 `$GITHUB_PAT` 或 `~/.github_pat`）。**若仍连通失败，立即停止并报告，不要伪造内容。**
- 不要手动写死 `140.82.113.x` 等旧 IP，一律依赖脚本自愈。

## 1. 摄取增量（首轮全量 / 之后增量）
- 读 `知识迭代/_迭代状态.md`：取 `needs_full`、`last_run`、`processed`。
- 若 `needs_full: true` 或 `last_run` 为空 → **全量**：处理 `灵感库/`（含 `灵感库/腾讯文档学习心得/`）与 `Topics/` 全部笔记。
- 否则 → **增量**：处理 `mtime > last_run` 的 `灵感库/` 笔记 + 期间新增/修改的 `Topics/` 笔记。
- **排除**（绝不处理，避免自指/死循环）：`知识迭代/` 自身全部文件、`_模板.md`、`_加工规范.md`、`_迭代协议.md`、`_每周归档提示词.md`、`_每日学习提示词.md`、`_已总结追踪.md`、各 `README*.md`、`Index.md`、任何以 `_` 开头的元文件、`*.docx/*.html/*.png/*.json`（非 md 内容）。
- 生成本轮「待处理清单」。

## 2. 连接建网（自动，机械低险）
对清单中每篇笔记 A：
- **抽取实体**：从 A 提取关键维度——成分/INCI（神经酰胺家族、肽类、PLLA、视黄醇、烟酰胺、玻色因、泛醇、积雪草、红没药醇、甘草酸二钾、角鲨烷…）、靶点/机制（TRP 通道、TSLP/IL-33、ILC2、Th2、胶原再生、终末分化、filaggrin、紧密连接、神经源性炎症、皮肤脑轴…）、产品概念（神经美容、医美术后、屏障修护、抗衰、美白、敏感肌、防晒…）。
- **全库匹配**：用 Grep 在 `灵感库/`、`Topics/`、`知识迭代/` 中检索上述实体，找出与 A 共享 ≥1 实体的其它笔记 B（排除 A 自身与第 1 步排除项），按共享实体数排序取 Top 3–6 作为关联。
- **正向链接**：在 A 末尾确保有 `## 关联` 段，写入 `[[相对路径/笔记名]]`（Obsidian 链接，不带 .md）。已存在则增量补充，不重复。
- **反向链接（幂等）**：在被指向的 B 末尾确保有 `## 相关增量` 段，追加 `[[A的相对路径/笔记名]]`；若已存在相同链接则跳过（幂等，可重复运行）。
- **刷新连接网络 MOC**：改写 `知识迭代/连接网络.md` 的「主题聚类」区——按主题桶（神经美容 / 医美术后 / 屏障生理 / 胶原再生 / 原料家族 / 配方工程）列出节点与边（形如 `A ↔ B（共享：神经酰胺）`）。保留「张力·矛盾」「缺口·待建卡」两区并填充。
- **张力·矛盾检测**：把相反视角并置（如 神经美容"感官刺激激活" ↔ 屏障修护"舒缓降刺激"；"补油封端" ↔ "先水后再油"递送顺序之争），记入 MOC 张力区与洞察。
- **缺口检测**：在 `灵感库/` 高频出现但 `Topics/` 无对应卡片的概念，记入 MOC 缺口区与洞察（作为待建卡建议）。
- 累计本次新建连接数。

## 3. 迭代新观点（生成提议，不直接改 Topics）
- 综合第 2 步被连接的簇，产出 **2–5 条新观点**（注意：**不是摘要**，是把多个笔记交叉后才有的"新东西"）。每条含：
  - **观点**：一句话犀利结论（允许有反对意见、有机智，带工程师×产品经理双视角）
  - **依据**：来自哪些双链笔记（列 `[[ ]]`）
  - **研发/产品落地启发**：可落地的配方/产品/沟通动作
  - **待验证假设**：一个可被实验或文献检验的命题
- 对已有 `Topics/` 卡片给出**修订建议**（补角度 / 补链接 / 补数据），**列为待确认，绝不直接改写 Topics 已确认结论**。
- 若本轮无足够交叉产生新观点，至少输出 1 条"连接状态 + 下一步建议"，不要硬编。

## 4. 落盘与推送
- 写 `知识迭代/周迭代洞察-YYYY-Www.md`（Www=年周，如 2026-W37），含：本期新增节点 / 新建立连接（Top 边）/ **迭代出的新观点** / 张力·缺口 / Topics 修订建议（待确认）/ 下一步。
- 更新 `知识迭代/_迭代状态.md`：`needs_full: false`、`last_run: 今天`、`last_run_iso`、`iteration_count +1`、`link_count += 本次新建连接数`、`processed: 本轮文件清单`。
- 推送：`bash ./sync-obsidian-kb.sh sync "kb: 周迭代 连接网络+新观点 (N节点/M连接)"`。

## 治理红线
- 不删除任何文件；不伪造内容；连通性失败即停报。
- **新观点 / Topics 修订只写进 `周迭代洞察-*.md` 提议，等你确认后并入；绝不自动改写 `Topics/` 结论**（守住"扳机在你"）。
- 非 md、以 `_` 开头的元文件、本目录自身一律不处理。
